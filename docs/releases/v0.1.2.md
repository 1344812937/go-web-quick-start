# OpenAI 网关控制台 v0.1.2

发布日期：2026-07-30

## 版本概述

`v0.1.2` 重点完善多客户端会话识别、渠道路由诊断和请求全阶段观测能力，同时优化渠道配置、运行总览及会话日志的可读性与稳定性。

## 更新内容

- 渠道基础配置与模型映射改为单次事务保存，避免配置分步提交，并统一渠道编辑流程。
- `/v1/models` 仅返回当前可路由模型，综合校验模型、映射及渠道启用状态和熔断状态。
- 新增文本 Token 估算接口；会话对话按消息展示 Token 估算，并增强 Codex 标题对结构化及代码块内容的解析能力。
- 完善会话切换诊断，模型切换时保留原渠道上下文，路由原因统一标记为 `model_switch`，会话详情同步展示当前渠道、迁移历史和路由决策。
- 建立 Codex 与 Copilot 的统一代理会话解析机制，持久化客户端类型、会话来源和客户端指纹，并增加近期会话查询索引。
- 完善 Copilot Chat 与 Responses 会话识别，优先使用稳定项目会话标识，支持历史回退、`prompt_cache_key`、初始标题及显式重命名结果持久化。
- 请求在访问上游前即以 `processing` 状态入库，完成后统一更新结果；会话统计单独展示处理中请求，并排除其成功率与平均耗时计算。
- 新增请求全阶段耗时追踪，覆盖鉴权、解析、会话识别、路由、重试、请求转换、上游交互、响应处理和持久化等阶段，记录微秒级耗时及网关准备时间。
- 优化会话日志与请求详情：新增客户端水印、消息来源标识、请求次数渐进强调、处理中状态提示及可折叠阶段瀑布；列表阶段默认折叠，请求详情默认展开，并限制约七条记录高度后内部滚动。
- 运行总览的渠道分布支持表格与饼图切换，可按请求次数或总费用统计，并完善键盘操作、图例、空状态和响应式布局。

## Copilot 识别配置

Copilot CLI 或兼容客户端调用 `POST /v1/chat/completions`、`POST /v1/responses` 时，必须在每次请求中附带以下固定请求头：

```http
X-Github-Copilot-Integration-Id: copilot-cli
```

客户端的自定义请求头配置应等价于：

```json
{
  "X-Github-Copilot-Integration-Id": "copilot-cli"
}
```

请求头缺失或值不匹配时，网关不会将请求识别为 Copilot。该请求头仅用于网关内部客户端识别，转发请求时会自动移除，不会发送至上游渠道。

## 修复问题

- 修复通过通用请求特征误判 Copilot 客户端的问题，改为校验固定集成标识，并阻止内部标识请求头转发至上游。
- 修复 Copilot 上下文压缩后稳定项目会话被拆分的问题；无稳定标识时仍使用严格历史匹配回退。
- 修复 Copilot Responses 会话分组、标题提取和重命名结果无法可靠持久化的问题。
- 修复请求完成前无记录、处理中请求被计入失败率和平均耗时的问题。
- 修复渠道基础配置保存成功但模型映射保存失败时产生部分提交的问题。
- 修复 `/v1/models` 返回当前无可用渠道或映射的模型问题。
- 修复模型切换诊断缺少原渠道上下文，导致路由原因和迁移记录不完整的问题。
- 修复会话时间线弹窗在挂载目标就绪前渲染导致的显示异常。
- 修复处理阶段列表展开后占用空间过大、缺少内部滚动的问题。
- 修复会话客户端水印显示不全，以及请求次数强调背景过重或字号超出显示范围的问题。
