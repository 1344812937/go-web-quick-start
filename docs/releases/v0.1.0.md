# OpenAI 网关控制台 v0.1.0

- 发布日期：2026-07-27
- 发布类型：首次正式发布
- 目标 Git 标签：`v0.1.0`
- 源码地址：[github.com/1344812937/go-web-quick-start/tree/v0.1.0](https://github.com/1344812937/go-web-quick-start/tree/v0.1.0)

## 版本概述

`v0.1.0` 是 OpenAI 网关控制台的首个正式版本。该版本提供一个可本地部署的 OpenAI 兼容多渠道网关，通过单个 Go 二进制同时提供转发服务和 Vue 3 管理控制台。

业务配置、管理员、令牌和日志保存在 SQLite 数据库 `data/data.db`；监听地址、超时和 Cookie 等运行设置保存在 `config/config.toml`；主密钥和首次管理员凭据从进程环境或当前工作目录的 `.env` 加载。

该版本适合内部服务接入、多个 OpenAI 兼容供应商的统一管理，以及模型路由、故障切换和费用观测能力验证。

## 主要功能

### OpenAI 兼容接口

- 支持 `GET /v1/models`。
- 支持 `POST /v1/chat/completions`。
- 支持 `POST /v1/responses`。
- 支持流式和非流式响应转发。
- 使用公开模型名接收请求，并在转发时替换为渠道配置的上游模型名。

### 多渠道模型路由

- 管理多个 OpenAI 兼容上游渠道、API Key 和模型映射。
- 支持优先级加权、最低成本和最低延迟三种路由策略。
- 优先级加权采用平滑加权轮询。同优先级渠道按累计权重余额分配，避免独立随机抽签产生长时间偏向单一渠道。
- 支持 Codex 会话亲和；已有会话优先使用此前成功的渠道。
- `Responses API` 请求携带 `previous_response_id` 时会回到原响应渠道，保持上游响应链一致。

### 重试、熔断与可观测性

- 默认单次请求最多尝试 3 个可用渠道。
- 网络错误、`408`、`429`、`5xx` 和非流式响应读取错误可触发渠道切换。
- 流式响应仅能在首个 SSE 事件尚未写给客户端时切换渠道；流已经开始后发生中断只记录错误，不会改用其他渠道续传。
- 渠道连续失败达到阈值后自动熔断，恢复后重新参与路由。
- 记录请求、每次上游尝试、切换前后渠道及稳定的切换原因代码。
- 提供最近五天的调用明细和会话渠道时间线；更早数据保留按令牌聚合的每日统计。

### 令牌、计费与管理控制台

- 签发、轮换和停用客户端访问令牌。
- 支持令牌模型授权、RPM 限制和并发限制。
- 统计输入、输出、缓存读取、缓存写入和实际发送 Token。
- 支持渠道与模型价格、价格倍率、预估费用和上游费用统计。
- 提供运行总览、渠道管理、模型路由、访问令牌、调用日志、Codex 会话和系统设置页面。

### 安全能力

- 管理控制台使用管理员账号和 `HttpOnly`、`SameSite=Strict` 会话 Cookie。
- 上游渠道 API Key 使用 `GATEWAY_MASTER_KEY` 通过 AES-GCM 加密后保存。
- 管理接口执行来源校验，并限制登录尝试频率。
- 客户端访问令牌只保存不可逆摘要。

## 运行要求

从源码构建需要：

- Go `1.25.4`
- Node.js `^20.19.0 || >=22.12.0`
- pnpm `10.23.0`

首次启动前必须设置：

| 环境变量 | 说明 |
| --- | --- |
| `GATEWAY_MASTER_KEY` | Base64 编码的 32 字节主密钥，可使用 `openssl rand -base64 32` 生成 |
| `GATEWAY_ADMIN_USERNAME` | 数据库中尚无管理员时用于创建首个管理员 |
| `GATEWAY_ADMIN_PASSWORD` | 首个管理员密码，至少 12 个字符 |
| `GATEWAY_OPEN_BROWSER` | 可选，默认 `true`；服务器部署建议设置为 `false` |

> `GATEWAY_MASTER_KEY` 用于解密已保存的上游凭据。数据库中已有渠道后不得更换或丢失该密钥。

## 构建发布产物

前端资源会嵌入 Go 二进制。构建发布包前执行：

```bash
pnpm --dir frontend install --frozen-lockfile
pnpm --dir frontend build
PACKAGE_NAME=openai-gateway ./build.sh
```

脚本生成以下产物，其中 `x86` 表示 64 位 x86-64，编译目标为 Go `amd64`，但发布文件名不使用 `amd64`：

```text
build/openai-gateway-linux-x86-0.1.0
build/openai-gateway-linux-arm64-0.1.0
build/openai-gateway-windows-x86-0.1.0.exe
build/openai-gateway-windows-arm64-0.1.0.exe
build/openai-gateway-darwin-x86-0.1.0
build/openai-gateway-darwin-arm64-0.1.0
```

Linux、Windows 和 macOS 均提供 x86-64 与 ARM64 版本。本版本不生成 32 位 x86 产物，产物文件名中也不再使用 `amd64`。

建议在上传 Release 资产前生成 SHA-256 校验文件：

```bash
shasum -a 256 build/openai-gateway-* > build/SHA256SUMS
```

## 启动与调用

新安装不需要预先创建 `config/` 或 `data/`。建议使用专用服务账号，并先创建仅该账号可访问的运行目录：

```bash
install -d -m 0700 openai-gateway-runtime
cp openai-gateway-linux-x86-0.1.0 openai-gateway-runtime/
cd openai-gateway-runtime
openssl rand -base64 32
```

将最后一条命令的输出填入权限受限的 `.env`：

```dotenv
GATEWAY_MASTER_KEY=<openssl rand -base64 32 的输出>
GATEWAY_ADMIN_USERNAME=admin
GATEWAY_ADMIN_PASSWORD=<至少 12 个字符的密码>
GATEWAY_OPEN_BROWSER=false
```

Linux 或 macOS 首次启动：

```bash
chmod 0600 .env
chmod 0755 openai-gateway-linux-x86-0.1.0
./openai-gateway-linux-x86-0.1.0
```

macOS 将上述文件名中的 `linux` 替换为 `darwin`。

Windows PowerShell 首次启动：

```powershell
.\openai-gateway-windows-x86-0.1.0.exe
```

以上示例使用 64 位 x86 文件名；ARM64 主机应改用对应的 `arm64` 产物。

Windows 部署也应使用专用服务账号，并通过目录 ACL 限制 `.env`、`config/`、`data/` 和 `logs/` 的访问。

应用会在当前工作目录自动创建 `config/config.toml` 和 `data/data.db`，缺失的必要配置会直接使用默认值或自动生成随机值，不再在服务启动时进行交互式配置引导。服务优先监听配置中的端口（默认 `8888`）；若端口被占用，会自动切换到其他可用端口。后续启动必须继续使用同一工作目录，否则应用会创建一套新的配置和数据库。

服务默认监听 `0.0.0.0:8888`，管理控制台地址为：

```text
http://127.0.0.1:8888/static/
```

使用 `.env` 中的首次管理员账号和密码登录，然后依次配置上游渠道、公开模型和客户端访问令牌。

OpenAI 兼容调用示例：

```bash
curl http://127.0.0.1:8888/v1/chat/completions \
  -H "Authorization: Bearer <gateway-token>" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "<public-model>",
    "messages": [{"role": "user", "content": "Hello"}]
  }'
```

## 升级说明

这是首个正式版本，没有受支持的更早正式版本升级路径。从任意开发分支或预发布构建升级不承诺数据兼容；应先在数据副本上完成验证：

1. 停止旧进程并备份 `data/data.db`、`.env` 和 `config/config.toml`。
2. 保持原有 `GATEWAY_MASTER_KEY` 不变。
3. 替换二进制后从原运行目录启动。应用会运行 GORM `AutoMigrate` 和当前版本内置的统计字段回填，但这不构成对任意历史开发数据库的兼容保证。
4. 登录管理控制台，检查渠道凭据、公开模型、令牌授权和系统设置。
5. 使用 `/v1/models` 和一个非流式模型请求完成冒烟验证。
6. 如果迁移或冒烟验证失败，停止新进程，恢复数据库和配置备份，再切回原二进制。

## 已知限制

- 平滑加权路由状态保存在当前网关进程内，进程重启或可用渠道集合变化后会重新开始权重周期。
- 会话亲和和 `previous_response_id` 路由优先于权重分配；同一长会话不会为了满足总体比例而切换渠道。
- 当前版本面向单实例 SQLite 部署，不提供跨实例共享的加权调度、限流或会话状态。
- 详细请求日志和会话时间线仅保留最近五天。
- Linux、Windows 和 macOS 均提供 ARM64 与 64 位 x86 产物；`x86` 文件名对应 Go `amd64` 编译目标。
- `build.sh` 不执行代码签名或 macOS notarization；下载方应使用 `SHA256SUMS` 校验产物完整性。
- 服务不直接终止 TLS。生产部署应在受信任的反向代理后提供 HTTPS，在系统设置中启用 `secure_cookie`，并限制默认 `0.0.0.0` 监听所暴露的管理端和网关端点。
